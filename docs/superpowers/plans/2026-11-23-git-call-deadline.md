# Git call deadline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `git` call from the Git projects collector that never answers is given up after 30 s, which frees
its slot. One lost call can then no longer freeze Git projects until Herdr restarts.

**Architecture:**
- The collector's `run()` races each `io.exec("git", …)` against a give-up. The give-up is registered when
  the call starts (inside its limiter slot), not when it is queued.
- `tick()` gives up every call past its deadline, comparing `io.now()`, the same way `ci-client.js`'s
  `sweep(now)` does for HTTP.
- A call that is given up answers `{ code: -1, stdout: "", stderr: "timeout" }`. Every caller already treats
  that shape as "git couldn't run" and retries it.
- `exec` also gets `timeout: 30000`, so Herdr kills a git process that is really hung.

**Tech Stack:** plain ES modules in `src/shared` (bundled into Herdr mods), `node --test`, esbuild via
`npm run build:app`.

**Spec:** `docs/superpowers/specs/2026-11-22-git-projects-design.md`, Anti-goals: "All git and HTTP work is
async and bounded … nothing hangs." There is no separate spec. The root cause below is the requirement.

## Root cause (investigated 2026-11-23 on the Mac)

- **Inputs were fine.** In the live app, `panes()` gave every terminal's real folder. `exec("git")` from a
  mod answered in about 15 ms, and dock-core's own samplers kept running `exec` every 5–10 s.
- **The collector ran no git for 111 minutes.** A new terminal in a repo never appeared, and ⟳ changed nothing.
- **Why:** `src/shared/collector.js:46` `run()` holds one of `limiter(4)`'s slots until `io.exec` settles, and
  nothing bounds that wait. Four execs that never settle leave every later git call waiting forever.
- **Likely trigger:** a herdr-core update. It relaunched the core at 09:43:13, while four distinct non-repo
  folders (home, `~/Dev/Workspace`, the Obsidian vault, `account-center-mf`) were waiting to be resolved. The
  first repo terminal opened at 09:43:35 and never resolved. This is not proven: the call is lost inside Herdr.

## Global Constraints

- `src/shared/*.js`: no Node built-ins and no `setTimeout`, since Herdr mods have none. Time comes only from
  `io.now()`, and work is scheduled on `tick()`, which dock-core calls every 1 s.
- At most 4 git processes at once (`GIT_LIMIT`), unchanged.
- The git deadline is **30 s** (`GIT_TIMEOUT = 30000`), the same as Herdr's own `exec` default. The HTTP timeout
  stays 15 s.
- Leave `src/shared/ci-client.js` alone. Its own deadline stays as it is.
- `app/` is a committed build. After the source change, run `npm run build:app` and commit `app/` in the same
  commit (`tests/build-app.test.mjs` compares them).
- Commit messages follow the repo's `fix(collector): …` style and end with
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- **Baseline on this Mac** (Node 22.14.0, after `npm ci`): 613 tests, 612 pass. The one failure,
  `tests/dock-core-class.test.mjs`, comes before this work and has nothing to do with it: it imports
  `registerHooks` from `node:module`, which needs Node ≥ 22.15.

## Review Focus

1. **A slow git that still answers** (20 s, say a `status` on a big repo) is used, not cut off. Test (c).
2. **A call queued behind lost ones** gets its own 30 s from when it starts. It must not give up in the
   same tick as the calls ahead of it. Test (a): the repo is listed at the 30 s tick.
3. **A `rev-parse` that was given up** is tried again, not cached as "not a repo", which would hide the repo until ⟳.
   Test (b).
4. **A `status` poll that was given up**: that worktree is polled again and its branch and ↑↓ update. Test (d).
5. **A worktree delete that never answers** ends in an error notification after 30 s, instead of nothing
   happening. Test (e).

```js
// --- git calls that never answer (docs/superpowers/plans/2026-11-23-git-call-deadline.md) ---
// A tick waiting on a lost call never ends, so these tests don't await tick(): tickAt runs it at fake time t and
// lets its git calls (1 ms each in fakeIo) and the follow-up work settle.
const lost = () => new Promise(() => {});
async function tickAt(io, c, t) {
  io.t = t;
  c.tick();
  await new Promise((r) => setTimeout(r, 20));
}
const oneSpace = [{ id: "s1", name: "a", machine: null, tabs: [{ id: "t1" }] }];
const LOCAL_TOOL = {
  " -C /w/tool remote get-url origin": NO_ORIGIN,
  " --no-optional-locks -C /w/tool status --porcelain=v2 --branch": status("main"),
};

test("lost git call (a): gives up after 30 s and frees its slot, so the call queued behind it runs", async () => {
  const dead = ["/w/l1", "/w/l2", "/w/l3", "/w/l4"];
  const io = fakeIo({
    platform: "linux", spaces: oneSpace,
    panes: [...dead, "/w/tool"].map((cwd, i) => ({ pane: `p${i}`, tab: "t1", cwd })),
    table: { ...Object.fromEntries(dead.map((d) => [` -C ${d} ${RP}`, lost])), [` -C /w/tool ${RP}`]: ok("/w/tool\n/w/tool/.git\n"), ...LOCAL_TOOL },
  });
  const c = createCollector(io);
  for (let t = 0; t <= 29000; t += 1000) await tickAt(io, c, t);
  assert.equal(callsTo(io, "/w/tool rev-parse"), 0, "queued behind the four lost calls");
  assert.deepEqual(c.state().repos, []);
  await tickAt(io, c, 30000);
  assert.deepEqual(c.state().repos.map((r) => r.name), ["tool"], "its own 30 s start when it runs, not when queued");
  for (const call of io.calls) assert.equal(call.timeout, 30000, call.key);
});

test("lost git call (b): a rev-parse that gave up is tried again, not cached as 'not a repo'", async () => {
  let n = 0;
  const io = fakeIo({
    platform: "linux", spaces: oneSpace, panes: [{ pane: "p1", tab: "t1", cwd: "/w/tool" }],
    table: { [` -C /w/tool ${RP}`]: () => (n++ ? ok("/w/tool\n/w/tool/.git\n") : lost()), ...LOCAL_TOOL },
  });
  const logs = [];
  io.log = (m) => logs.push(m);
  const c = createCollector(io);
  for (let t = 0; t <= 31000; t += 1000) await tickAt(io, c, t);
  assert.equal(callsTo(io, "/w/tool rev-parse"), 2);
  assert.deepEqual(c.state().repos.map((r) => r.name), ["tool"]);
  assert.ok(logs.some((m) => m.includes("/w/tool") && m.includes("timeout")), logs.join("\n"));
});

test("lost git call (c): a slow answer inside 30 s is used, never given up", async () => {
  let answer;
  const io = fakeIo({
    platform: "linux", spaces: oneSpace, panes: [{ pane: "p1", tab: "t1", cwd: "/w/tool" }],
    table: { [` -C /w/tool ${RP}`]: () => new Promise((r) => { answer = r; }), ...LOCAL_TOOL },
  });
  const logs = [];
  io.log = (m) => logs.push(m);
  const c = createCollector(io);
  for (let t = 0; t <= 20000; t += 1000) await tickAt(io, c, t);
  answer(ok("/w/tool\n/w/tool/.git\n"));
  for (let t = 21000; t <= 45000; t += 1000) await tickAt(io, c, t);
  assert.deepEqual(c.state().repos.map((r) => r.name), ["tool"]);
  assert.equal(callsTo(io, "/w/tool rev-parse"), 1);
  assert.equal(logs.some((m) => m.includes("timeout")), false, logs.join("\n"));
});

test("lost git call (d): a status poll that gave up is polled again, and its worktree updates", async () => {
  let s = 0;
  const io = fakeIo({
    platform: "linux", spaces: oneSpace, panes: [{ pane: "p1", tab: "t1", cwd: "/w/tool" }],
    table: {
      ...LOCAL_TOOL,
      [` -C /w/tool ${RP}`]: ok("/w/tool\n/w/tool/.git\n"),
      " --no-optional-locks -C /w/tool status --porcelain=v2 --branch": () => (s++ ? status("main", { ab: "+1 -0" }) : lost()),
    },
  });
  const c = createCollector(io);
  for (let t = 0; t <= 29000; t += 1000) await tickAt(io, c, t);
  assert.equal(c.state().repos[0].worktrees[0].branch, null, "no status yet");
  for (let t = 30000; t <= 31000; t += 1000) await tickAt(io, c, t);
  assert.equal(callsTo(io, "/w/tool status"), 2);
  assert.equal(c.state().repos[0].worktrees[0].branch, "main");
  assert.equal(c.state().repos[0].worktrees[0].ahead, 1);
});

test("lost git call (e): a worktree delete that never answers ends in an error notification after 30 s", async () => {
  const io = fakeIo({ repos: [{ path: "D:/work/api", machine: null }], table: { ...API, " -C D:/work/api worktree remove D:/work/api-login": lost } });
  const notes = [];
  io.notify = (n) => notes.push(n);
  const c = createCollector(io);
  await c.tick();
  const done = c.deleteWorktree("|d:/work/api-login");
  for (let t = 1000; t <= 30000; t += 1000) await tickAt(io, c, t);
  const r = await Promise.race([done, new Promise((res) => setTimeout(() => res("still waiting"), 100))]);
  assert.deepEqual(r, { ok: false, error: "timeout" });
  assert.equal(notes.length, 1);
  assert.equal(notes[0].body, "timeout");
});
```

- [ ] **Step 5: Implement the deadline in `src/shared/collector.js`**

- Add `const GIT_TIMEOUT = 30000;` after `GIT_LIMIT`, commented as how long a git call may take before it is
  given up, the same as Herdr's `exec` default.
- In `createCollector`: keep a `Set` of running git calls, each `{ deadline, giveUp }`.
- `run(machine, args)`: inside the `git(async () => …)` slot, so the deadline starts when the call starts:
  - register `{ deadline: io.now() + GIT_TIMEOUT, giveUp }`;
  - race `io.exec("git", args, { on: machine ?? undefined, timeout: GIT_TIMEOUT })` against `giveUp`;
  - a rejected exec still answers `{ code: -1, stdout: "", stderr: <message> }`, as today;
  - `giveUp` settles the race with `{ code: -1, stdout: "", stderr: "timeout" }`;
  - remove the entry once the race settles.
- `tick()`: right after `client.sweep(now)`, give up every entry with `now >= deadline`.
