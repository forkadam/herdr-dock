# Jira page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A dock page, `dock-jira`, for the company's self-hosted Jira (Server / Data Center): the user's issues and
saved filters as a list or a board, an issue's detail, quick actions (status, assign to me, comment, open in browser)
and **Start work** (a Claude tab whose first message comes from a template). Built and tested at home against a mock
Jira; checked against the real one at the office.

**Architecture:** Everything that can be pure is: JQL, request building, response → view model, grouping, the
Start-work text, error classification (`src/shared/jira/*.js`, unit-tested). Requests go through a two-way
**transport**: Herdr's `fetch`, or `curl` through `exec` (for a company certificate Herdr's `fetch` won't trust). The
mod only renders, keeps state and calls the client. A mock server (`scripts/mock-jira.mjs`) answers the same REST v2
endpoints with fixtures and keeps changes in memory.

**Tech Stack:** Herdr mods (gpui-kit / gpui-base / herdr), esbuild via `scripts/build.mjs`, `node --test`, Node's
`http` for the mock (no dependencies).

**Spec:** `docs/superpowers/specs/2026-11-22-dock-pages-jira-design.md` (Part 2).

## Global Constraints

- Jira **REST API v2** only, **Bearer PAT** auth (`Authorization: Bearer <token>`). Jira Cloud is out of scope.
- The token is never in the repo, `config/dock.json`, `local.json`, shared state, a log line, an error message or a
  process's arguments. It lives in `<app home>/herdr-dock/secrets/jira-<site>.token` (and the curl config beside it),
  mode 600 on macOS / Linux.
- Other settings (base URL, Start-work template, extra JQL filters) live in `<app home>/herdr-dock/jira-<site>.json`,
  written by the page's Settings form. The page's only prop is `site` (default `"work"`), so two Jira sites could
  be two pages later.
- `dock-jira` is page-only (`PAGE_ONLY` in `src/shared/config.js`). It is **not** in the shared default config (it is
  company-specific); the user adds it on a PC through the Dock layout dialog.
- Start work: `tab.new {name: key, argv: ["claude"], task}` in the selected space, then `showTerminal()`. No branch,
  no worktree, no Jira change.
- Polling: every 2 min while the page is shown (`pageShown("dock-jira")`), every 10 min while hidden (for the
  badge), and after a failure no sooner than 5 min. A manual refresh always runs.
- Badge: `dock.page.badge.dock-jira = { count: <assigned to me, unresolved>, tone: "info" }`; null while not
  connected.
- View (list / board) per PC: shared `dock.jira.view`.
- New code follows the repo's style: pure modules without host imports under `src/shared/`, small mods, comments say
  why.

## Review Focus

- A token leak path: the curl transport must read the token from a `-K` config file, never `-H` on the command line;
  error texts must not echo request headers. (Task 3 test `curl args never contain the token`.)
- A 401 shows "token rejected" with the Connect form, not an empty list (Task 2 test `classify: 401 → auth`).
- Changing filters quickly: an older response arriving after a newer one must not replace it (Task 5: each fetch
  carries a sequence number; stale results are dropped; test `latestOnly drops an older response`).
- A transition list is per issue and per moment (workflows differ): fetched when the Status menu opens, never cached
  across issues.
- The Start-work template with a missing placeholder value (no description) leaves no `{…}` in the message (Task 2
  test `startTask fills every placeholder, empty when missing`).

### Task 1: Mock Jira server

**Files:**
- Create: `scripts/mock-jira.mjs`, `tests/fixtures/jira/issues.json`, `tests/fixtures/jira/filters.json`,
  `tests/fixtures/jira/workflow.json`
- Modify: `package.json` (`"mock:jira": "node scripts/mock-jira.mjs"`)
- Test: `tests/mock-jira.test.mjs`

**Interfaces:**
- `startMock({ port = 8089, token = "mock-token", slowMs = 0, failStatus = null }) -> Promise<{ url, close() }>`
  (exported for tests; the CLI calls it with `--port`, `--slow`, `--status`).
- Endpoints, with Jira's JSON shapes: `GET /rest/api/2/serverInfo` (no auth), `GET /rest/api/2/myself`,
  `GET /rest/api/2/search?jql&fields&startAt&maxResults`, `GET /rest/api/2/issue/{key}`,
  `GET /rest/api/2/filter/favourite`, `GET|POST /rest/api/2/issue/{key}/transitions`,
  `PUT /rest/api/2/issue/{key}/assignee`, `POST /rest/api/2/issue/{key}/comment`.
- Errors in Jira's shape: `{ "errorMessages": [...], "errors": {} }`; 401 without the right Bearer token; 404 for an
  unknown key; 400 for JQL outside the subset.

- [x] **Step 1: Fixtures.** ~30 issues in projects `WEB`, `API`, `OPS`: types Bug / Task / Story, priorities, statuses
  To Do / In Progress / In Review / Done (categories `new` / `indeterminate` / `done`), assignee `me` on about half,
  created/updated spread over two weeks, descriptions in Jira wiki markup, 0–4 comments each. Two favourite filters
  (`My open bugs`, `API this sprint`). A workflow: To Do → In Progress → In Review → Done, and back to To Do.
- [x] **Step 2: Tests first** (`tests/mock-jira.test.mjs`, start the mock on port 0): 401 without token; `myself`;
  search with each supported JQL clause and `ORDER BY updated DESC`; `startAt` paging; unsupported JQL → 400;
  transitions list follows the workflow; POST transition moves the issue (a later search sees it); assignee PUT; a
  comment POST appears in the issue; `--status 500` → every authed call 500.
- [x] **Step 3: Implement** with `node:http`, state cloned from the fixtures per start. JQL subset parser:
  `assignee = currentUser()`, `reporter = currentUser()`, `project = X`, `status = "Y"`, `statusCategory != Done`,
  `resolution = Unresolved`, `text ~ "q"`, `key in (A-1, B-2)`, joined by `AND`, optional
  `ORDER BY updated|created|priority ASC|DESC`. Everything else → 400 with Jira's error shape.
- [x] **Step 4:** `npm run mock:jira` prints the URL and the token to use.

### Task 2: Pure Jira model

**Files:**
- Create: `src/shared/jira/model.js`, `src/shared/jira/jql.js`
- Test: `tests/jira-model.test.mjs`

**Interfaces:**
- `BUILTIN_FILTERS`: `[{ id: "mine", name: "Assigned to me", jql: "assignee = currentUser() AND resolution = Unresolved ORDER BY updated DESC" }, { id: "reported", … }, { id: "recent", name: "Updated recently", jql: "assignee = currentUser() AND updated >= -14d ORDER BY updated DESC" }]`
- `withSearch(jql, text) -> jql` (adds `text ~ "…"` with quotes escaped, before any `ORDER BY`)
- `searchUrl(base, jql, { startAt, maxResults }) -> string` (fields: summary, status, issuetype, priority,
  assignee, updated)
- `issueRow(issue, base) -> { key, summary, type, typeIcon, priority, status, category, assignee, updatedMs, url }`
- `groupByCategory(rows) -> [{ category: "new"|"indeterminate"|"done", title, rows }]` (empty groups left out)
- `boardColumns(rows) -> [{ status, category, rows }]` (ordered by category, then first appearance)
- `issueDetail(issue, base) -> { …row, description, comments: [{ author, bodyText, createdMs }] (last 5), links }`
- `wikiToText(markup) -> string` (strip `{code}`/`{noformat}` markers, `h1.`, `*bold*`, `[text|url]` → `text (url)`)
- `classify({ status, data, error, curlCode }) -> { kind: "auth"|"forbidden"|"notfound"|"invalid"|"server"|"offline"|"tls"|"timeout"|"unknown", message, hint, fields? }`
  (`invalid` is any 400: bad JQL, or a workflow step wanting `fields`)
- `startTask(template, detail) -> string` and `DEFAULT_START_TASK = "Work on Jira issue {key}: {summary}\n{url}"`
- `latestOnly()` → `{ next(): seq, accept(seq): boolean }` (drop stale responses)
- `ago(ms, now) -> "2h"`

- [x] **Step 1: Tests first** for every function above, using `tests/fixtures/jira/issues.json` shapes:
  grouping order and empty groups; board column order; `withSearch` escaping and ORDER BY placement; `wikiToText`
  cases; `classify` for 401, 403, 404, 400 with `errorMessages`, 500, a `fetch` rejection with "certificate" /
  "self signed" / "UNABLE_TO_VERIFY" (→ tls), "ECONNREFUSED" / "dns" / "network" (→ offline), timeout; curl exit
  codes 6/7 (→ offline), 28 (→ timeout), 35/51/58/60 (→ tls); `startTask` with every placeholder and with missing
  values (no `{…}` left); `latestOnly`.
- [x] **Step 2: Implement** until green. No host imports.

### Task 3: Transport and client

**Files:**
- Create: `src/shared/jira/transport.js` (pure: builds what to run), `src/shared/jira/client.js` (runs it, with
  Herdr's `fetch` / `exec` handed in as `io`, so Node tests it directly)
- Test: `tests/jira-transport.test.mjs`, `tests/jira-client.test.mjs` (client against the mock, with Node's `fetch`
  and `child_process` injected in place of Herdr's)

**Interfaces:**
- `fetchRequest({ method, url, token, body }) -> { url, options: { method, headers, body } }`
- `curlArgs({ method, url, configPath, body }) -> string[]` — `-sS`, `-K <configPath>`, `-X`, `-H "Accept: application/json"`,
  `-H "Content-Type: application/json"` with a body, `--data-binary <json>`, `--max-time 20`,
  `-w "\n%{http_code}"`, the URL. The token is only in the `-K` file.
- `curlConfig(token) -> string` (`header = "Authorization: Bearer <token>"`, with `"` and `\` escaped)
- `parseCurl(stdout, code) -> { status, text } | { error: { curlCode } }`
- `createClient({ base, transport: "fetch"|"curl", token, curlConfigPath, io: { fetch, exec } })` →
  `myself()`, `search(jql, page)`, `issue(key)`, `favouriteFilters()`, `transitions(key)`, `transition(key, id)`,
  `assign(key, name)`, `comment(key, text)`, `serverInfo()`. Each resolves `{ ok: true, data }` or
  `{ ok: false, problem: classify(…) }` (plus kind `nocurl` when curl can't start); never throws. A `fetch` timeout
  needs `io.sleep` (the mod passes `cx.sleep`).

- [x] **Step 1: Tests first:** `curlArgs` never contains the token (property test over several tokens);
  `curlConfig` escaping; `parseCurl` splits body and status, maps a nonzero exit code; the client against the mock for
  each call, for 401 (wrong token), the mock stopped (offline), `--slow` past the timeout, `--status 500`.
- [x] **Step 2: Implement.** In the mod, `io.fetch` is Herdr's `fetch` and `io.exec` is Herdr's `exec`.

### Task 4: Settings, Connect and the token file

**Files:**
- Create: `src/shared/jira/settings.js` (pure), `src/shared/jira/store.js` (reads/writes with Herdr's file calls handed
  in: `loadJira`, `saveSettings`, `saveToken`, `clearToken`)
- Test: `tests/jira-settings.test.mjs`

**Interfaces:**
- Paths from `appHome()` and `site`: `settingsPath`, `tokenPath`, `curlConfigPath`.
- `parseSettings(text) -> { ok, settings: { v: 1, baseUrl, transport, startTask, filters: [{ name, jql }] } }` with
  defaults; `normalizeBaseUrl(text)` (trims, drops a trailing `/`, a `/secure/…` or `/browse/…` tail, requires
  http(s)).
- Connect flow: the secrets folder is created and made 700 first (one `node -e` call; nothing is written if that
  fails), then the token file and the curl config, then both set to 600 (`node -e` chmod; skipped on Windows, where
  the profile folder is private); then the page calls `myself()` to check. On failure the files stay, and the form
  shows the problem.
- Disconnect: overwrite the token and curl config with empty text (Herdr has no delete API) and forget the user.

- [x] **Step 1: Tests first** for `parseSettings` (junk → defaults, unknown keys kept), `normalizeBaseUrl` cases,
  the path builders (Windows and POSIX homes).
- [x] **Step 2: Implement.**

### Task 5: The dock-jira page (read-only)

**Files:**
- Create: `src/mods/dock-jira/{main.js,manifest.json,mod.json,icon.svg,refresh.svg}`, `src/shared/jira/page.js` (pure:
  filter list, poll timing, page state, badge, counts; `tests/jira-page.test.mjs`)
- Modify: `src/shared/config.js` (`PAGE_ONLY` += `dock-jira`)
- Test: `tests/pages.test.mjs` (placement), `herdr-app check app/mods/dock-jira`

**What it does:**
- States, each with what to do: *not set up* → Settings form (Jira URL, token, transport fetch / curl, Start-work
  template); *checking*; *problem* (from `classify`: token rejected → Connect again; offline → "Not reachable: are
  you on the company network?"; tls → "Switch to curl" button; invalid → Jira's own message); *ready*.
- Header: "Jira", the site host, the filter picker (built-ins, favourite filters, the user's own), a search box
  (Enter applies), the list / board toggle, refresh, "updated 2m ago", a gear (Settings).
- List view (default) and board view as in the spec; selecting an issue opens the detail on the right (420px,
  resizable later); Esc-free: a close button.
- Detail: key, summary, status pill, type, priority, assignee, description (`wikiToText`), last 5 comments, links,
  "Open in browser".
- Polling and badge as in the Global Constraints; `latestOnly` around every search.

- [x] **Step 1:** Build against the mock (`npm run mock:jira`, URL `http://127.0.0.1:8089`, token `mock-token`).
- [x] **Step 2:** `herdr-app check`, then try it live: every state (stop the mock for *offline*, wrong token for
  *auth*, `--status 500`), both views, a long list, the badge.

**As built, beyond the plan:**
- Commands for keys.json and testing: `dock-jira.list|board|refresh|settings|next|prev|close`.
- Board columns follow Jira's own status order (`GET /rest/api/2/status`, added to the client and the mock).
- Herdr's `fetch` reports every failure to connect as "error sending request" with no cause, so a refused
  connection, DNS and a rejected certificate look alike: that counts as *offline*, its hint names the certificate,
  and the page offers **Switch to curl** for it too. Error texts drop URLs.
- `\n` typed in the one-line Start-work field means a line break.
