# herdr-dock

A whole Herdr window rebuilt as a dock. On the left a panel with your spaces, your agents, your Git projects with their CI badges and your Claude and Codex usage limits. Across the top a tab bar with a panel toggle. In the middle your terminal in one rounded pane. On the far right an icon rail that opens a panel of Pipelines, Notifications, Files or Changes. Along the bottom a quiet status bar. Every region can be rearranged from a dialog, per PC.

![herdr-dock](preview.png)

## What you see

The layout (`layouts/herdr-dock.json`) is a row with no title bar, canvas background and 14/12 terminal padding, split by 1px `border` dividers.

- **Left panel** (`dock-left`, 268px, resizable 44 to 480, `chrome` background), top to bottom:
  - Header (46px, drags the window): app name and a search button.
  - Spaces (flexible): your spaces, click to select.
  - Agents (flexible): your agents grouped by status; each Claude row can show its context as "NN%".
  - Git projects (flexible): repos and worktrees with git status and a CI badge (passed, failed, running, warning).
  - Quotas (270px): per provider (Claude with its plan, Codex, Antigravity with its plan), one line per window (5-hour, weekly, per-model weekly): label, bar with a pace tick (how much of the window has passed), "15%", time to reset ("2h 04m"); the full detail is in its tooltip.
  - Footer (40px): buttons for the layout dialog, adding, and settings.
- **Work area** (`dock-work`), top to bottom:
  - Top bar (42px, drags the window): the panel toggle (44px) then the tab bar with a right-panel button beside "+" and window buttons.
  - Body: the active tab's terminal in a pane (radius 10, `background` color, 1px `border`, 1px `accent` focus border, 8px gap) with a 30px pane header; then the **right panel** (`dock-right`, 360px, 280 to 900, hidden at first) and the **rail** (`dock-rail`, 40px, `chrome` background) with one icon per right mod.
  - Bottom bar (28px): Where, Limits (a strip of usage limits: per provider its icon, then `5h ▬| 17%  wk ▬| 20%  Fable |─ 0%` with pace ticks, the time to reset from 70% up; resting the pointer opens the full panel), Warnings (210px), System (150px), Notifications bell (36px).
- A toast overlay (`dock-toast`) shows notifications like Herdr's own.

## How it behaves

- **Agent status:** working shows a spinning icon; blocked shows a red "Needs you" pill (a "!" when compact); done shows a filled dot, idle a hollow ring. Agents are ordered blocked, done, working, idle.
- **Left panel modes:** Ctrl+Alt+B (or the top-bar toggle) cycles expanded (everything), icons (a 48px rail; click an icon to expand with that feature tall), hidden (no panel).
- **Dock pages:** the Pages bar in the left panel (a row of icons on a raised strip: Terminal first, then each page with a count badge in its corner; the shown one on a raised tile) shows a page in place of the terminal; clicking the page shown, any tab, space or agent, or Ctrl+Alt+P cycling past the last page brings the terminal back. One page at a time; remembered per PC.
- **Jira page** (`dock-jira`): a self-hosted Jira (Server / Data Center), connected with a personal access token; its settings file is `herdr-dock/jira-<site>.json`.
  - **Tabs** under the header, each with its count: **Today**, then the person's own tabs (`views` in the settings file, in their order), then the built-ins **Mine** (assigned to you, unresolved) and **All** (everything assigned to you, resolved too, with the filter menu: All my issues, Assigned to me, Reported by me, Recently viewed, Jira's favourite filters and the settings' `filters`). A view is `{ "id", "name", "jql", "group"?, "button"? }`: the id is lower-case letters, digits and dashes, starting with a letter; `"group": "type"` lists its issues by issue type first; a view with the id `mine` or `all` replaces that built-in's name and search (and may carry a button too). `"button": { "label", "task" }` draws one button in that tab's header, right of the search box (never on Today); a click opens a Claude tab named after the label with `task` as its first message (a typed `\n` is a line break) and shows the terminal, with no Jira request; a button without a label or a task is skipped with a line in Settings and the tab stays, and the tooltip is the message it sends. Each tab keeps its own search text, rows, open issue and List / Board choice while Herdr runs; the shown tab, each tab's List / Board and All's filter are remembered per PC (`dock.jira.tab`, `dock.jira.layout.<id>`, `dock.jira.filter.all`). The other tabs' counts refresh every 10 minutes; a tab whose search Jira rejects shows `!` and says why, and the others carry on. Commands `dock-jira.tab-next`, `dock-jira.tab-prev` and `dock-jira.tab-<id>`. For example `"views": [{ "id": "bugs", "name": "Bugs", "jql": "issuetype = Bug AND assignee = currentUser() AND resolution = Unresolved", "button": { "label": "Triage all", "task": "/triage" } }]`.
  - **Today**: the brief, above the sprint board when a Scrum board is set (alone otherwise). The brief looks back to the current sprint's start (14 days without one) and lists **Changed** (description edits by someone else on your unresolved issues and on the parents of your sub-tasks; the issue's detail opens with the description's line diff, Mark read, and Check against my work: a Claude tab named `<key> check` with the `checkTask` message, which names the issue and when it changed, never the description's text), **New in sprint** (your issues that became yours in the sprint after it started: added to it, a carry-over from the sprint before not counting; created in it; or assigned to you) and **High-priority bugs** (the `briefBugs` JQL narrowed to `highPriorities`). The board is the current sprint (the active sprint holding most of your issues) in the board's own columns, one lane per parent story; dragging a card to another column runs that move. Settings has **Scrum board** (type part of a scrum board's name and pick it; kept as `board`, its id; No board removes it) and **High priorities** (your Jira's names for urgent priorities, comma-separated; default Highest, High). The **sprint menu** (the sprint's name) lists its series, the sprints whose name differs only by its number (`Sprint 41`, `Sprint 42`): the next one, the active one and the last 5 closed; with no active sprint Today says so. **Read marks** are per PC (`dock.jira.read`): opening an issue reads its New-in-sprint and bug items; a Changed item is read only by Mark read or Mark all read. The **Pages badge**, and Today's count, is the number of unread items, warning-coloured while a high-priority bug is unread. A Today request that fails while Jira is reachable (a slow search, any failure of the agile API) is said on the board or in the brief and as `!` on Today's tab. Each refresh asks one search for your changed issues and one per 50 parents (reading only when each issue was last updated), the sprint's search and the bugs search; the history Changed reads is fetched apart, one search per 50 issues that are new to the window or were updated since their history was fetched (most refreshes fetch none); the board's columns, statuses and active and future sprints (Jira Software's agile REST API, `/rest/agile/1.0`) once an hour, and its closed sprints when the sprint menu first opens after each of those reads (right away when no sprint is active).
  - **Start work and Finish**: Start work (detail button, a row's ▶, command `dock-jira.start`) opens a Claude tab named after the issue with a first message from the settings' template. The settings file (`herdr-dock/jira-<site>.json`) can also hold `actions`: a list of rules, **the first whose keys all match the issue wins**, each with optional match keys `project` (the key's prefix), `type` (issue type name), `subtask` (`true` / `false`) and `parentType` (the parent's issue type name, or a list), and the messages `start` and `finish` (placeholders `{key} {summary} {url} {type} {status} {priority} {assignee} {description}`). Start work sends the matched rule's `start`, else the settings' message. **Finish** is a detail button (command `dock-jira.finish`) shown only when the matched rule has a `finish`: it opens a Claude tab named `<key> finish` with that message. The page changes nothing in Jira itself. For example `"actions": [{ "project": "SEC", "start": "/triage {key}" }, { "type": "Bug", "finish": "/close-bug {key}" }]`.
- **Right panel:** Ctrl+Alt+N or the tab-bar button shows or hides it; clicking a rail icon shows that mod, clicking the active one hides the panel. The state is remembered per PC.
- **Ctrl+Alt+,** opens the **Dock layout** dialog (760 wide, 80% high): move features between regions, resize, switch modes, reset this PC. Saves go to this PC only (`~/.config/herdr-app/herdr-dock/local.json`).
- **Bottom bar:** Warnings shows running pipelines, a quota at 90% or more, and low disk; System shows CPU and memory %, in the warning color from 90%; the bell is red when something needs you, accent when only unread. Anything fine shows nothing.
- **Git projects** polls git status (15s for open worktrees, 1 min others) and CI (30s running, 5 min otherwise); a failed pipeline raises a notification once.
- **Notifications** records every toast (cap 200); clicking one runs its action.
- **Updates:** the Dock layout dialog has an Updates strip that checks GitHub when Herdr starts and every 6 hours and offers Update.

## Built from

- **Layout node tree:** `root` row (`toast: dock-toast`) with children `dock-left` (column of blocks `dock-left-N-<mod>`) and `dock-work` (column: `dock-top` row, `dock-mid` row, `dock-bottom` row). `dock-mid` holds `dock-body` (row, padding 8, gap 8: the `dock-main` block with `content.tab: "active"` (with pages configured, inside a stack `dock-work-stack` beside one block `dock-page-<i>-<mod>` per page, `dockRegion: "pages"`) and a `pane` config whose header is Herdr's shipped `pane` mod; and the `dock-right` column holding a `stack` `dock-right-stack` of the four right mods) and the `dock-rail` block. Every block's content is `{mod, props: {dockFeature: <block id>, dockRegion: left|top|right|bottom}}`.
- **Mods** (all `place: "none"`, in `mods/`): `dock-core` (panel modes, layout rewriting from config, update check, notification history, system sampling), `dock-header`, `dock-spaces`, `dock-agents`, `dock-git`, `dock-quotas`, `dock-pages` (the Pages bar), `dock-footer`, `dock-tabs`, `dock-rail`, `dock-pipelines`, `dock-notifications`, `dock-files`, `dock-changes`, `dock-where`, `dock-limits`, `dock-render` (right panel: the focused agent's latest answer, its diagrams and its folder's Markdown files, drawn, with Mermaid diagrams and figures drawn by a bundled helper), `dock-warnings`, `dock-system`, `dock-attention`, the pages `dock-overview` and `dock-jira` (a self-hosted Jira: issues as a list or board, detail, status / assign / comment, Start work and Finish), and overlays `dock-config` (dialog, 760 x 80%), `dock-git-delete`, `dock-toast`. Each has `manifest.json`, `mod.json`, `main.js` and its SVG art. `dock-core` also ships `config.json` (the region config), `VERSION.json`, `source.json` and `update-app.mjs`; `dock-quotas` ships `herdr-statusline-cache.mjs` (the writer Claude Code's status line runs), `herdr-statusline-setup.mjs` (puts it there) and `herdr-claude-usage.mjs` (asks the `claude` CLI for your limits) and `herdr-agy-statusline.mjs` (Antigravity's status-line writer; set up in `~/.gemini/antigravity-cli/settings.json` with `herdr-statusline-setup.mjs --agy`).
- **Shipped Herdr mods used:** `pane` (the pane header, and its `close.svg` on tabs and the window's close button); `workspace-chrome` (its icons: `spinner`, `chevron-right`, `chevron-down`, `plus`, `check`, `branch`, `monitor`, `server`, `pin`, `pin-off`, `clock`, `layers`); `files` (its `file.svg`, the Files rail icon) and `changes` (its `changes.svg`, the Changes rail icon) when those panels are in the right region; `picker` (opened by the header's search button through `mod.open`); `machine-add` (opened by the footer's Add machine button through `mod.open`, and by Spaces); `menu` (the right-click menu of a tab or a space) and `new-menu` (the tab bar's "+"), opened as popups.
- **Keys** (`keys.json`, section `layout:herdr-dock`): `ctrl-alt-b` runs `dock-core.cycle`, `ctrl-alt-,` runs `dock-core.config`, `ctrl-alt-n` runs `dock-core.right`, `ctrl-alt-p` runs `dock-core.page`.
- **Herdr commands:** `herdr-app do dock-core.cycle|expanded|icons|hidden|reload|right|config|page|terminals`; the mods read spaces, agents and tabs through Herdr's API and share state through Herdr's shared keys (`dock.*`).
- **Programs run** (through the mods' `exec`, plus the update tab):
  - `git` (status, worktrees, diffs, the update clone); `gh` (and `glab` for GitLab hosts: CI tokens and API calls and, in app mode, the published-version check); `node` (the system sampler, folder creation, `update-app.mjs`, `herdr-statusline-setup.mjs`, `herdr-claude-usage.mjs` every 5 minutes, the Jira page's folder and permission setup, and Claude Code runs the writer with it); `claude` (asked for your usage limits by `herdr-claude-usage.mjs`, as `/usage` does: its own sign-in, no model use); `curl` (the Jira page, when its connection is set to curl); `herdr-app` (`herdr-app check` of every new mod during an update).
  - Windows: `powershell` (Herdr's own CPU and memory; `dock-files` lists folders), `cmd` (`dir`, to list mods and Codex session folders), `findstr` (Codex `rate_limits` lines), `hostname`, `rundll32` (open a CI page in the browser), `explorer` (open a folder).
  - macOS / Linux: `ps` (Herdr's own CPU and memory), `sh` (`dock-files` lists folders), `ls`, `grep`, `hostname` (macOS) or `uname -n` (Linux), `open` (macOS) or `xdg-open` (Linux) for pages and folders.
- **Network:** `raw.githubusercontent.com` and `api.github.com` (update check), the CI APIs of the hosts of your repos, GitHub (the update clone), and, when the Jira page is placed and connected, the company Jira the person enters (REST API v2). With the browser turned on, `registry.npmjs.org` (the agent-browser download, checked against a pinned checksum) and, when no `chrome` path is set, Chrome for Testing's download host.
- **Files written outside the mod folders:** `~/.claude/settings.json` and `~/.gemini/antigravity-cli/settings.json` (their `statusLine`, by `herdr-statusline-setup.mjs`, after a `.bak-herdr-dock` copy), `~/.gemini/antigravity-cli/statusline-cache/` (by the Antigravity writer), `~/.claude/statusline-cache/` (by the writer), `local.json` (below); with the browser turned on, `~/.claude/skills/dock-browser/`, `~/.codex/skills/dock-browser/` and (where it has a `skills` folder) `~/.gemini/config/skills/dock-browser/` (the dock-browser skill, by `herdr-browser-setup.mjs`) and `herdr-dock/browser/` (agent-browser's binary, the signed-in profile, session records); with the Jira page, `herdr-dock/jira-<site>.json` and `herdr-dock/secrets/jira-<site>.token` / `.curlrc` / `.body` (the secrets folder 700, the files 600, set with `node`); `herdr-dock/render/` (Render's diagrams, tidied after each read: unused for 14 days or past the newest 300).
- **Files read outside the mod folders:** `~/.claude/statusline-cache/claude-statusline.json` (Claude limits and context), `~/.claude/sessions/`, `~/.codex/sessions/**/rollout-*.jsonl` (Codex limits), your repos' working folders, and `~/.config/herdr-app/herdr-dock/local.json` (the per-PC overrides, which the dialog also writes).

## Watch out

- **Don't rename anything.** The dock mods refer to each other by name (`dock-core` rewrites the layout, `dock-rail` and `dock-tabs` call the others); the layout must stay `layouts/herdr-dock.json`.
- **If any `dock-*` mod or `layouts/herdr-dock.json` already exists, stop and ask the person.** Do not overwrite or rename. A machine installed from a clone of the repo updates with `npm run update` in that clone; use one install per machine.
- **Tell the person before adding:** it runs programs (git, gh, glab, node, herdr-app; on Windows PowerShell, cmd, findstr, hostname, rundll32, explorer; elsewhere ps, sh, ls, grep, hostname or uname, open or xdg-open); it uses Herdr's shipped `pane`, `workspace-chrome`, `files`, `changes`, `picker`, `machine-add`, `menu` and `new-menu` mods (icons and the dialogs it opens); it reaches the network (GitHub for updates and CI, their repos' CI hosts); it reads the Claude and Codex usage files listed above; and it sets Claude Code's status line in `~/.claude/settings.json` (and Antigravity's in `~/.gemini/antigravity-cli/settings.json` when that folder exists).
- **Claude's numbers need herdr-dock's writer in Claude Code's status line.** After copying the mods, run `node <app home>/mods/dock-quotas/herdr-statusline-setup.mjs` and tell the person what it printed. It edits `~/.claude/settings.json` (backup: `settings.json.bak-herdr-dock`): with no status line it adds one that prints nothing; with a one-command status line it puts the writer in front (`node "<writer>" --tee | <theirs>`, which prints the same); a status line that already feeds herdr-dock or is more than one command is left alone (for the latter, offer the one line from the README, "Where the quota and context numbers come from"). No `~/.claude`: it does nothing. If it didn't run, Quotas shows "Claude: status line not set up" with a **Set up** button that runs the same script. Codex needs nothing.
- **Ask first: turn on the browser beside agents?** Off by default. If they say yes, the person can turn it on themselves in the Dock layout dialog's **Browser** section (Ctrl+Alt+, or the layout button in the left panel footer): they pick a Chrome found on this PC or Chrome for Testing, click **Turn on**, and a **Set up the browser** tab runs the setup script below and shows the result; **Turn off** there removes it. Or you do it: set `"browser": { "enabled": true }` in `<app home>/herdr-dock/local.json` (add `"chrome": "<path to Chrome or Chromium>"` to use one already installed; without it Chrome for Testing, about 150 MB, is downloaded), then run `node <app home>/mods/dock-browser/herdr-browser-setup.mjs` and tell the person what it printed. It downloads agent-browser (about 20 MB; checked against a pinned checksum), gets Chrome, and writes the `dock-browser` skill for Claude Code, Codex and Antigravity where their folders exist (`--no-skills` skips that; `--check` only reports). If they say no, do nothing; `dock-browser` stays out of the layout. Turning it off later: set `enabled` to false and run the same script, which removes the binary and the skills (the signed-in profile stays).
- **Merge `keys.json`** into the person's: add the section and keys, ask before replacing one already in use.
- **Updates** come through the Dock layout dialog's Updates strip: Update opens a tab running `mods/dock-core/update-app.mjs`, which clones the repo into a temp folder, checks every mod, swaps the mods in and rolls back on failure. The layout, keys and `local.json` are left alone; missing keys are added.
- **The repo is private for now**: the agent installing it (and the update) needs `gh` logged in and set up for git (`gh auth status`, then `gh auth setup-git`).
- The right panel starts hidden.

## Done when

- `herdr-app check` passes for every `mods/dock-*` folder.
- `layout.switch {name: "herdr-dock"}` shows the left panel with Header, Spaces, Agents, Git projects, Quotas and Footer, the tab bar on top, the terminal pane in the middle and the 28px bottom bar; the right panel is hidden but the rail is on the far right.
- Ctrl+Alt+B cycles the left panel expanded, icons (a 48px rail), hidden, and back to expanded.
- Ctrl+Alt+N (or the tab-bar button) shows the right panel with Pipelines, and again hides it; a rail icon switches to Notifications, Files or Changes.
- The bottom bar shows a computer icon with the machine name and a branch icon with the branch on the left, the CPU and memory icons with their %, and the bell at the far right.
- `~/.claude/settings.json` has a `statusLine` whose command (or its script) runs `herdr-statusline-cache.mjs`, unless the person has no Claude Code or chose to add the line themselves; after one Claude Code reply, Quotas shows the Claude block.
- Ctrl+Alt+, opens the Dock layout dialog (760 wide) with the Updates strip at its top.
- A notification that needs the person turns the bell red and appears in Notifications with a "resolved" mark once its cause is fixed.
- A running agent shows a spinner and a blocked one a red "Needs you" pill in Agents.
